# 相册附件改造与半屏拍照方案

日期：2026-11-03。本文以用户最新取舍为准，不再把全量官方同步当作本次交付条件。

## 1. 本次交付范围

- 加号面板保留拍照、照片、文件入口，在入口下方横向预览最近照片，可连续多选。
- 点选立即导入当前消息草稿，再点取消选择；长按缩略图可放大预览。
- 单张和多张相册图片都不自动打开编辑器；原系统相册仍可选取更多图片。
- 输入框图片以缩略图展示，右上角半透明圆形 ✘ 删除，点击图片进入原生裁剪页面。
- 裁剪成功替换原位置，不额外新增一张；取消裁剪保留原图。
- 移除加号面板的“压缩历史”条目，原上下文圆环和压缩能力保留。
- 本次不实现半屏相机，不推进 Room 26→32，不为非必需官方交互扩大范围。

## 2. 实现边界与兼容

- 相册预览仅请求读取图片，不请求视频访问。权限在点击“允许访问”时申请，不在应用启动时申请。
- Android 14 及以上兼容“仅选择的照片”授权，并提供重新选择授权照片的入口；拒绝授权仍可使用上方系统相册。
- 返回前台重新检查真实权限并查询，不永久缓存权限状态。权限处理参考 [Android 官方文档](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)。
- 仅查询最近 60 张可访问照片的 URI；缩略图按显示尺寸加载，更多图片从系统相册选择，避免整本相册原图解码。
- 文件流式复制和登记在后台串行进行；关闭选择面板不取消已选择的导入。
- 导入期间取消、删除、清空草稿或切换编辑对象后，迟到结果不能进入其他草稿，未接收的本次文件被清理。
- 同一来源 URI 不重复加入；不同系统选择器可能给同一图片返回不同 URI，不承诺跨 URI 内容级去重。
- 删除/裁剪编辑中的历史附件不会直接删除历史文件；新添的草稿文件才按当前操作清理。
- 原 `skipCropImage` 字段保留备份兼容，聊天相册不再用它决定是否自动编辑；设置页改为新交互说明。
- 默认上下文 1M/472k、预设提供商、莫奈蓝风格、英语模块、签名、包名和工具链保持不变。

## 3. 拍照升级：仅方案，等待相册手测后再实施

目标：点击拍照后在半屏弹窗内显示相机预览；拍摄后图片直接进入消息框，有入框过渡，不自动打开裁剪；点击附件仍可裁剪。

难度：**中等偏高**。这不是把系统拍照 Activity 改成半屏尺寸；需要自建 CameraX 预览与拍摄界面。

预计工作量（粗估，非交付承诺）：基础拍照与半屏界面约 4–8 小时；生命周期、方向/EXIF、动画及不同设备兼容打磨另约 4–8 小时，合计约 1–2 个工作日。具体以真机反馈和现有依赖适配为准。

建议分两步：

1. 半屏预览、前后摄像头、拍摄、取消、拍后直接导入；沿用本次草稿导入与点击裁剪链路。
2. 入框动画、横竖屏/刘海/大字体、前后台切换和失败恢复打磨。

必须处理：相机拒权/无相机、摄像头被占用、弹窗关闭释放相机、生命周期解绑、旋转与镜像、拍摄中重复点击、低内存、草稿切换，以及拍摄失败的临时文件清理。动画不应依赖高分辨率 Bitmap 常驻。

现有工程已经引用 CameraX core，缓存中也存在 camera2/lifecycle/view；正式实现前仍需核对模块声明和版本，不擅自升级或安装依赖。

## 4. 本次手测清单

1. 打开加号，首次拒绝权限：应用不崩，照片入口仍能多选。
2. 完整授权后显示最近照片；部分授权只显示允许的照片，管理授权后刷新。
3. 连续选择多张，取消其中一张，再点“完成”：输入框与勾选一致，不出现裁剪队列。
4. 系统相册分别选 1 张、多张：全部直接加入输入框，不自动编辑。
5. 点附件 ✘：仅移除对应图片；再次打开加号时对应来源不再勾选。
6. 点附件裁剪、确认：原位置更新且张数不变；取消裁剪：原图保留。
7. 编辑带图的历史消息，裁剪或移除后取消编辑，原历史图片仍可打开。
8. 导入多张时立即关闭面板、取消选择、清空草稿或切换对话，确认无迟到图片串入新消息。
9. 横屏、大字体、深浅色下检查面板可滚动、删除按钮可点、原主题一致。
10. 拍照本次仍是原来的系统相机＋拍后确认；上下文圆环仍可压缩。
