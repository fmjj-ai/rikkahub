# 流式可视化 v2 实现记录

本次在已有原生 v1 引擎上增加 `rikka-viz-stream`。模型每输出一条换行结束的合法 JSON 记录，客户端即更新图形，不等待 Markdown 围栏闭合。原来的完整 `rikka-viz` 保持兼容。

## 行为与接入

- 原文 Markdown AST 识别顶层 v1/v2 围栏，保持行结束符及真实闭合状态。关闭围栏的反引号尚未输出完整时，不把它误当成 JSON。引用、列表、HTML 和普通代码中的标记不会自动运行。
- 同一 Markdown 文档中用内部占位围栏承载图块，保留引用链接、公式、表格及 HTML 路径。仅图块数据发生变化时复用原 AST/DOM。
- Markdown 快照有序处理并合并中间输入，持续流式输出不会因反复取消解析而一直不显示；目标刷新间隔约 50ms，未做设备帧率承诺。
- v2 缓存键固定为对话、消息版本、part 和围栏序号，不使用正文 hash；v1 仍使用内容摘要区分修改。Compose 图块不随新增 token 重建。
- 解析与用户操作串行协调；整条操作验证通过后原子更新 spec/frame。新声明的状态补充初值，已有用户交互值不被覆盖。重置恢复最新声明的初值并保留已经生成的图形。
- 错误记录冻结该流，保留本分片中最后一条有效记录及其画面，显示错误和源码入口。取消时不执行尚未换行的记录，保留已完成部分；闭合时允许验证提交最后一条无换行但完整的记录。缺少 done 标为未完成。
- v1/v2 共用 48 项 LRU，随聊天 ViewModel 生命周期回收；删除或切换版本清理不再显示的消息缓存。进程重启重新从原始记录构建初值。
- v2 通知和朗读提取 init 标题，不朗读大段 NDJSON。历史、分享、复制和导出保留原始正文。

## v2 记录格式

首条 init，version=2，无 seq。必需字段是 op、version、id、width、height；title、state、actions 可选。主画布在这时建立。

后续 seq 从 1 连续递增，每条一行：

- `shape` / `replace`：`op,seq,id,data`，追加或替换主画布图元。
- `remove`：`op,seq,id`，删除主画布已有图元。
- `node` / `replaceNode`：`op,seq,id,data`，追加或替换主画布后面的视图节点，包括文字、按钮、滑块及布局。
- `removeNode`：`op,seq,id`，删除附加视图节点。
- `state`：`op,seq,key,value`，仅新增状态初值。
- `action`：`op,seq,id,data`，仅新增动作定义。状态和动作必须在引用它们的图元或控件之前声明。
- `done`：`op,seq`，终止流；其后只允许空白。

图元和附加节点的记录 id 必须唯一且稳定，data 不重复写 id。表达式、视图和图元复用 v1，包含相同类型校验与资源预算。v2 总文本不超过 64 KiB、单条记录不超过 8 KiB、最多 512 条记录；完整初值场景也必须通过 v1 的字节、深度、数组、图元及采样限制。每条消息 v1/v2 合计最多自动显示 4 块。

完整交互示例已放在 `VizPrompt.kt`，测试会提取真实提示词中的围栏执行，避免示例与实现脱节。

## 生成配色与提示词开销

配色只增强模型生成图形的提示，没有修改应用主题、增加配色选择控件或引入 palette 协议。

提示模型每图选 3–5 种协调低饱和色区分模块、保持同类同色；给出马卡龙、莫兰迪十六进制参考值。浅色填充配深色文字和描边，透明背景文字使用主题语义色，避免只用颜色传递含义。最终效果由模型生成内容决定。

- 原版：2788 字符、4660 UTF-8 字节，项目估算约 1399 tokens。
- 当前：3630 字符、6266 UTF-8 字节，项目估算约 1897 tokens，增加约 498 tokens。
- 估算使用现有 `String.estimateTokens()`：ASCII 按 1/4 token、非 ASCII 按 1 token。不同模型 tokenizer 有差异，不含消息封装开销，不作为账单精确值。
- 仅当助手「交互式可视化」能力和全局显示开关均开启时加入主聊天请求；单次请求只追加一次，不写入历史或用户自定义提示词，也不注入标题、翻译、压缩任务。
