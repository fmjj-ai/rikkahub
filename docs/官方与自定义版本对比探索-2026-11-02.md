## 1. 结论先看

建议方向是：**采用官方的新业务底座，移植你的独有功能，并保留你当前的视觉设计和配置偏好。**

这不是把官方目录直接覆盖到你的目录，也不是整份保留你的旧文件。官方已经重构 AI 请求、会话状态、工具执行、设置存储和通用 UI；整文件二选一容易同时丢掉功能和修复。

### 1.1 你明确询问的三个功能

1. **一个 URL 支持多协议：官方没有与你等价的统一管理方案，但有绕行实现。**
   - 官方提供 OpenAI、Google、Claude 等不同提供商类型，并保留模型级 `providerOverwrite`，可以给模型单独覆盖协议和配置。
   - 因此，“同一个地址用于不同协议的请求”可以通过多条提供商配置或模型覆盖实现。
   - 但官方没有你的 `MultiProtocol` 服务商、模型 `protocol` 字段、共享 URL 的三协议配置面板，以及同 URL 提供商合并流程。
   - **按你的需求，保留你的多协议能力和管理体验，适配官方新类型体系。** 不应把“可以覆盖单个模型”误判为“官方已经完整支持你的方案”。

2. **聊天页面调用子代理生图：官方没有与你的 `draw_image` 等价的内置链路。**
   - 官方存在模型原生图片输出、OpenAI Responses 内置 `image_generation`，也有独立的媒体创作系统。
   - 这些与“当前聊天主模型调用另一个已配置的生图模型，再把图片返回聊天”不是同一能力。
   - 你的实现是本地工具 `draw_image`，实质是主模型通过工具委托生图子模型；不是一套通用、多轮自治的子代理框架。
   - **保留你的聊天生图工具、聊天内展示、半成品预览和图库归档。** 独立媒体创作如何接入，见问题 Q5。

3. **一次性压缩对话：官方支持，而且支持默认压缩全部活动上下文。**
   - 入口：聊天加号面板 → 压缩对话 → 确认；可以补充要求、设置保留最近消息数，默认保留数为 `0`。
   - 这里的“全部”是最后一个摘要检查点之后的活动范围；此前历史通过已有摘要参与上下文，不是反复重发所有原始历史。
   - 官方使用同一个聊天模型、同一套请求组装，在末尾追加总结要求，插入摘要检查点；原消息仍可查看。
   - **没有发现你的 472k 阈值自动压缩机制。** 手动一次压缩、自动触发压缩、超长文本分块压缩，需要分别看待。
   - 官方的压缩输入仍须能被模型接受；“一次操作”不等于任意长度必定一个请求成功。推荐组合方案，见问题 Q1。

### 3.3 手动压缩、自动压缩、摘要保存

**你的实现特点**

- 超过 `472,000` token 阈值，或输入加预留输出超过窗口时，尝试自动压缩。
- 有独立压缩模型设置；找不到时回退聊天模型。
- 默认摘要目标约 `2,000` token，默认保留最近 `4` 条，并对齐完整用户轮次；最新一轮及工具调用链保留。
- 大文本按预算分块，顺序总结，再合并多块摘要。
- 展开文档和 OCR 文本，不再对每条消息只取固定前缀。
- 原始记录保留，摘要挂在旧消息的 `contextCompaction` 字段上。
- 使用消息内容指纹校验，历史编辑、分支内容变化后旧摘要会失效。
- 自动压缩输入预算来自模型设置，不是固定 32k。但超过预算时仍可能多次请求，并非无条件一个请求。

**官方实现特点**

- 手动压缩支持“全部压缩”和保留最近 N 条；默认 N 为 `0`。
- 使用当前聊天模型、系统提示、工具定义、会话参数和请求构造，再追加总结要求，有利于复用请求前缀缓存。
- 摘要作为可见检查点插入时间线，原始记录仍保留。
- 会阻止生成中压缩、待压缩范围含未完成工具调用等情况。
- 摘要生成后向最新会话状态插入，避免直接写回旧整份会话。
- 压缩请求不沿用聊天回复的输出上限，避免结构化摘要被较小输出设置截断。
- 未发现你的阈值自动触发、独立压缩模型、目标摘要 token 控制和通用分块合并机制。

**优劣判断**

- 官方：更贴合新会话架构，保留工具/多模态请求结构，缓存复用条件更好；但整段本身过大时仍可能失败，也不能指定便宜的独立压缩模型。
- 你的：长历史容错、自动触发、预算控制更强；但转为独立文本总结会改变请求前缀，图片主要变成占位信息，并且指纹/全文估算会增加大上下文计算量。
- 两者都保留原记录，不能把区别描述为“官方保留、你的删除”。

**处理建议：采用官方检查点和请求框架，保留你的自动阈值、边界校验和超长分块能力。** 具体运行策略需你选择，见 Q1。

旧 `contextCompaction` 与新 `isContextCheckpoint` 是两种持久化表示。必须转换或兼容读取已有摘要，不能只换 UI。你的摘要指纹校验不能在迁移时无声消失。

自动压缩不能直接套用官方手动入口：官方入口会拒绝“生成中”状态，而你的自动压缩发生在生成流程内部。应在请求开始前串行执行，或抽出可复用的内部总结操作；不能为了复用入口而取消并发保护。

### 3.8 后台生成保活

**你的方案**：前台服务、任务集合、可关闭的后台保活开关、Partial WakeLock；最后一个任务结束后延迟 1.5 秒收尾，压缩任务也纳入跟踪。
